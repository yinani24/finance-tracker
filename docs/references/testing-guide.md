# Testing Guide Reference

This document covers the test suite structure, how to run tests, the 100% coverage requirement, fixture strategy, and patterns for writing new tests.

---

## Running Tests

```bash
# Run all tests (no coverage)
pytest

# Run all tests with coverage report
pytest --cov=. --cov-report=term-missing

# Run a specific file
pytest tests/test_dashboard_data.py -v

# Run a specific test
pytest tests/test_dashboard_data.py::test_build_context_empty -v

# Run with short tracebacks
pytest -q
```

### Coverage Enforcement

`pytest.ini` enforces 100% code coverage:

```ini
[pytest]
addopts = --cov=. --cov-fail-under=100 --cov-omit=tests/fixtures/make_pdf_fixtures.py
```

A run that drops below 100% will **exit non-zero** and block CI. The fixture generator script `tests/fixtures/make_pdf_fixtures.py` is excluded from coverage because it is a one-time utility, not application code.

To run without the coverage check (faster during development):

```bash
pytest -p no:cov
```

## Fixtures

### CSV Fixtures

Located at the top of each test file. Created inline with `io.StringIO` or `tmp_path`:

```python
import io, csv, pytest

@pytest.fixture
def chase_csv(tmp_path):
    content = "Transaction Date,Description,Amount\n01/15/2026,CHIPOTLE #1234,-45.20\n"
    f = tmp_path / "chase.csv"
    f.write_text(content)
    return str(f)
```

### PDF Fixtures

Pre-generated binary files in `tests/fixtures/`:

| File | Generated by | Used by |
|------|-------------|---------|
| `chase_sample.pdf` | `make_chase_pdf()` | `test_csv_parser.py`, `test_pdf_parser.py`, `test_import_real_data.py` |
| `bofa_visa_sample.pdf` | `make_bofa_visa_pdf()` | `test_import_real_data.py`, `test_pdf_parser.py` |
| `bofa_checking_sample.pdf` | `make_bofa_checking_pdf()` | `test_import_real_data.py` |
| `robinhood_sample.pdf` | `make_robinhood_pdf()` | `test_import_real_data.py` |
| `robinhood_sample.csv` | Created by `make_robinhood_csv()` | `test_import_real_data.py` |

**Regenerating fixtures:**

```bash
python tests/fixtures/make_pdf_fixtures.py
```

Run this once after cloning, or after modifying the fixture generator. The generated PDFs are committed to the repository.

**Why pre-generated:** PDF generation via `reportlab` is slow. Pre-generating once and committing the binary means tests run quickly without needing `reportlab` at test time.

**Important:** The Paragraph-based BofA and Robinhood fixtures produce text that does not always match the real-statement regex patterns. Tests for those parsers use `assert added >= 0` or test return types rather than asserting specific transaction counts.

### DataStore Fixtures

Most tests use `tmp_path` to create isolated CSV files:

```python
def test_add_transaction(tmp_path):
    path = str(tmp_path / "transactions.csv")
    store = DataStore(transactions_path=path)
    tx = { "id": "abc123", "date": "2026-01-15", ... }
    store.add(tx)
    df = store.load()
    assert len(df) == 1
```

### Deterministic Dates

Pass `today=date(2026, 3, 26)` when calling `build_context()` or any function that accepts a `today` parameter to make test assertions date-independent:

```python
from datetime import date
ctx = build_context(df, accounts, goals, today=date(2026, 3, 26))
assert ctx["kpis"]["this_month"] == "2026-03"
```

## Test Patterns

### Testing CLI Commands

Use Click's `CliRunner` to test CLI commands without spawning a subprocess:

```python
from click.testing import CliRunner
from finance import cli

def test_summary_empty(tmp_path):
    runner = CliRunner()
    result = runner.invoke(cli, ["summary", "--data-dir", str(tmp_path)])
    assert result.exit_code == 0
    assert "No transactions found" in result.output
```

### Testing Import Functions

Pass a `DataStore` backed by `tmp_path` and a minimal config:

```python
import json, pytest
from data_store import DataStore
from import_real_data import parse_chase_credit_pdf

def test_parse_chase_returns_list(tmp_path):
    store = DataStore(transactions_path=str(tmp_path / "tx.csv"))
    added, skipped = parse_chase_credit_pdf(
        "tests/fixtures/chase_sample.pdf",
        store=store,
        account="Chase-CreditCard",
        cat=Categorizer(),
        closing_year=2024,
        closing_month=1,
    )
    assert isinstance(added, int)
    assert isinstance(skipped, int)
```

### Testing the Security Scripts

`test_check_secrets.py` creates temporary files using `tmp_path` and feeds them directly to `scan_file()`:

```python
from scripts.check_secrets import scan_file

def test_detects_account_number(tmp_path):
    f = tmp_path / "bad.py"
    f.write_text('account = "1234 5678 9012 3456"\n')
    findings = scan_file(str(f))
    assert len(findings) > 0
```

### Testing Analytics Functions

Use small synthetic DataFrames with `pd.Timestamp` dates:

```python
import pandas as pd
from datetime import date
from dashboard_data import compute_kpis

def test_kpis_correct_month(tmp_path):
    df = pd.DataFrame([
        {"date": pd.Timestamp("2026-03-10"), "amount": -50.0, ...},
        {"date": pd.Timestamp("2026-02-10"), "amount": -30.0, ...},  # prior month
    ])
    kpis = compute_kpis(df, {"accounts": []}, {}, today=date(2026, 3, 26))
    assert kpis["expenses"] == 50.0  # only current month
```

## Coverage Notes

### What must be covered

All application code in the repo root and `importers/` directory:

```
categorizer.py
dashboard.py
dashboard_data.py
data_store.py
finance.py
goals.py
import_real_data.py
importers/csv_parser.py
importers/pdf_parser.py
scripts/check_changelog.py
scripts/check_secrets.py
```

### What is excluded

- `tests/fixtures/make_pdf_fixtures.py` — fixture generator, excluded via `--cov-omit`
- `tests/` directory itself — pytest does not instrument test files for coverage by default

### Handling hard-to-cover branches

Some branches are only reachable in rare conditions (e.g., a `KeyError` inside `_normalize_row()`). Cover them explicitly rather than using `# pragma: no cover`:

```python
def test_normalize_row_returns_none_for_missing_amount(tmp_path):
    parser = PDFParser()
    result = parser._normalize_row({"Date": "01/15/2026"}, "chase", "Chase", "pdf")
    assert result is None  # missing Amount key raises KeyError → returns None
```

## Adding Tests for a New Feature

1. Write the test file (or add to an existing one) in `tests/`.
2. Follow TDD: write the failing test first, then implement the feature.
3. After implementation: `pytest --cov=. --cov-report=term-missing` to verify 100% coverage.
4. If adding a new module at the repo root or in `importers/`, ensure it is included in coverage (it is by default since `--cov=.` covers everything except the explicit omit list).
