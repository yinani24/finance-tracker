## What I found (primary-source, this run)
The **Cards page can create a manual card but can neither edit nor delete one** — the same "endpoint with no client fn / no render site" gap #109/#111 and #114/#115 closed:
- Backend has **full CRUD**: `PATCH /cards/{card_id}` (`CardUpdate`) and `DELETE /cards/{card_id}` both mounted (`app/api/cards.py:35`/`:52`).
- Web side: `api.ts` had `getCards`/`createCard`/`deleteCard` — but **`deleteCard` was referenced nowhere in the UI** (grep → only its own def) and there was **no `updateCard` at all**. `cards/page.tsx` imported only `getCards, createCard`.
- Consequence: a typo in a card's name, a wrong annual fee, or a wrong network was **permanent** (delete-and-re-add impossible — no delete button either).

**Why worth shipping:** a manual card's `annual_fee` + `rewards_config_json` feed the **recommendation engine's existing-card math** (first-year-value net-of-fee; earn rates). Editing is the correction path for the very data the engine optimizes over. **Consumer-side only — user's own portfolio, not the card-bonuses catalog → not blocked by #38 or #72**, no Plaid keys.
