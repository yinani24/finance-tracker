synchronous `setState`. Replaced each with the React-idiomatic equivalent,
preserving behavior **and** SSR/hydration safety:

- **New `src/lib/use-hydrated.ts`** — `useHydrated()` via `useSyncExternalStore`
  (server snapshot `false`, client snapshot `true`). The canonical replacement for
  a `useState(false)` + `useEffect(() => setMounted(true), [])` hydration flag: no
  setState-in-effect, and React hydrates with the server snapshot then swaps to the
  client one, so no markup mismatch.
- **`top-bar.tsx`** — `mounted` now from `useHydrated()`.
- **`session-context.tsx`** — `ready` from `useHydrated()`; the session is restored
  from `sessionStorage` in a **lazy `useState` initializer** (`readStored()` is
  SSR-safe — it swallows the server-side `sessionStorage` ReferenceError) instead of
  a restore effect. Dropped the `hydrated` ref; the persist effect now guards on
  `!ready` (and lists `ready` in deps, so no new `exhaustive-deps` warning).
- **`sidebar.tsx`** — the persisted `collapsed` flag is read via
  `useSyncExternalStore` backed by a small module-level `localStorage` store
  (server snapshot `false`); `toggle()` writes through it and notifies listeners.
  Restores collapse state without a setState-in-effect and keeps sidebars in sync.
- **`transactions/page.tsx`** — the "reset to page 1 when filters change" effect
  became an **adjust-state-during-render** off a `filterKey` (React's
