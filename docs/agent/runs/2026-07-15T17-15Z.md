## The bug (found by reading merged #128, not from any journal)
The `/explore` page (merged in #128, closing #123) shows a correct total in its header
("Browse N cards") but **"No cards match your filters"** in the grid for *every* query.

- **Backend, tested contract:** `GET /card-bonuses` →
  `apps/api/app/services/card_bonuses.py::search_cards` returns `{total, limit, offset, results}`;
  `tests/test_card_bonuses.py` asserts `body["results"]` (endpoint test + 10 more).
- **Frontend, wrong:** `types.ts::CardBonusSearchResult` declared `cards: CardBonus[]` and
  `explore/page.tsx` read `data?.cards` → **`undefined` at runtime** → `cards = []` always.
- **Why it slipped in:** issue #123's body mis-described the endpoint as returning `{cards, total}`;
  the implementation matched the issue text, not the real endpoint. The hand-maintained TS type
  hid it from `tsc`. `total` is a real field, so only the grid (not the header) went blank — a
  visible, self-contradictory failure.
