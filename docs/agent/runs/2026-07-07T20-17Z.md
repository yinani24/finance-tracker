# Run 2026-07-07T20-17Z

**Stage 4 (Implement) — Issue #8: Plaid webhook verification (Plaid-Verification JWT).**

## What I advanced
Closed the last open Plaid Phase-1 slice and the latent security gap flagged in
PR #15: `POST /plaid/webhook` was accepting unauthenticated requests because
`verify_webhook()` was still a `return True` stub after #7 (PR #13) merged.

Implemented real verification on branch `agent/8-plaid-webhook-verify`:

- `app/services/plaid_webhook.py` — real ES256 `Plaid-Verification` JWT check:
  pin `alg=ES256` (rejects `alg=none`/HS256 confusion), fetch the signing key
  from `/webhook_verification_key/get` by `kid` **cached process-locally** (no
  per-request fetch; rotation = new `kid` = cache miss), enforce a **5-minute
  `iat`** replay window, and compare the `request_body_sha256` claim to the raw
  body hash **constant-time** (`hmac.compare_digest`). Any failure → route 401.
- `app/config.py` + `.env.example` — `FT_PLAID_WEBHOOK_VERIFY` flag, **defaults
  enabled**; off is the local/sandbox escape hatch. Also documented the
  previously-undocumented `FT_PLAID_WEBHOOK_URL`.
- `app/api/plaid.py` — refreshed the now-stale route docstring.
- `tests/test_plaid_webhook.py` — existing #7 functional tests run with the flag
  **off** (they POST unsigned bodies); new `TestWebhookVerification` class runs
  with it **on**: valid→200+sync, missing header→401, tampered body→401, bad
  signature→401, stale `iat`→401, wrong `alg`→401, key cached by `kid` (one
  fetch for two same-`kid` webhooks), flag-disabled skips. Hermetic — mints an
  in-test EC P-256 keypair and mocks the key endpoint; no network, no secrets.
- `CHANGELOG.md` — `[Unreleased]` entry.
