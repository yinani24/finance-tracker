## What I found (primary-source, this run)
A **fully-shipped, mounted statement-import backend with zero web wiring** — the
exact "endpoint with no client fn / no render site" gap that #109/#111 closed for
recategorization:
- `POST /imports` (multipart `file` + `account_id`) → `run_import()` parses a CSV,
  **dedupes**, creates transactions, returns `ImportSummary`
  (`total_rows/added/duplicates/skipped`); bad files → `400` with a helpful
  `StatementParseError`. `GET /imports` + `GET /imports/{id}` for history.
  Mounted at `app/api/router.py:19`. **CSV-only today** (`statement_import.py`).
- Web side: **no `createImport`/`getImports` in `api.ts`; zero `/imports`
  references under `apps/web/src`** (grep → 0). No upload UI.

**Why it's worth shipping:** this is the **keys-free path to get real transaction
history into the app** (Plaid linking needs live keys + an owner-local step; CSV
import needs neither). Transaction history is the input to the entire product loop
— spending profile → insights → recommendations. Consumer-side only, **no card
data → not blocked by #38 or #72.**
