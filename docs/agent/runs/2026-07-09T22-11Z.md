## Decision — advance a genuinely unblocked correctness fix (not gated on #38)
The only backlog issue (#38) is human-blocked and no PR was in flight, so per the charter
("advance a genuinely unblocked correctness fix… never open a filler PR") I surveyed the engine
for a real, self-contained bug rather than manufacture busywork.

**Bug found (verified against `main` @ `ec7144e` + the live sibling dataset):**
`analyze_portfolio`'s alternative-suggestion loop excluded only the *exact* card being analyzed
(`alt_key == key`) — unlike `recommend_next_card`, which skips **discontinued** cards and **all**
already-owned cards. So the wallet-analysis surface could tell a user to "switch to":
- a **discontinued** card — the dataset (`credit-card-bonuses-api/exports/data.json`, 179 cards)
  has **5 discontinued, 3 of them $0-fee** (US Bank Altitude Reserve 2%, US Bank Smartly 2%, Amex
  Everyday). A $0-fee 2% card clears the `alt_fee <= annual_fee` gate and out-nets a mediocre held
  card, so it would surface as a top alternative you can't actually apply for.
- a card the user **already holds** (the loop only skipped the analyzed card, not their other
  cards). Both are actively wrong advice in the app's core "should I keep this card?" surface.
No category data, no human decision needed — fully unblocked.
